## Контракты
1. **Каталог ассетов (A12)** — `assets/catalog/*.json` (каждый агент пишет свой файл), загрузчик `scripts/core/asset_catalog.gd` (пишет A первым коммитом; B, C, E читают). Запись:
   `{"id": "plant_alocasia_big", "name": "Алоказия крупная", "category": "plant|tree|rock|ground|creature|sea|bird|insect|item|food|weapon|vehicle|character", "scene": "res://…glb или .tscn", "lod": ["res://…LOD1.glb"], "zones": ["jungle","forest_edge","beach","dunes","palm_belt","lowland_forest","rocks","mangrove","lagoon","reef_crest","reef_slope","ocean","cave"], "size_m": [w,h,d], "collision": "none|soft|solid", "hitbox": "capsule|box|mesh_simple", "density": 1.0, "cluster": 0.0..1.0, "source": "KODAK путь", "license": "…", "climate_ok": true|false, "tags": []}`.
   `collision`: none — трава/мелочь; soft — кусты, алоказия, папоротники (замедляют, раздвигаются); solid — стволы, маленькие пальмы, камни. Реакцию soft/solid рядом с игроком делает C (создание коллизий рядом), замедление в soft — F (player), визуальный изгиб — D.
2. **Генератор (C) → полигон (E):** `IslandGenV5.build(recipe_id, seed, origin) -> Node3D` и `ArchipelagoV5.layout(seed) -> Array[island descriptors]`, стриминг `IslandStreamer.ensure(center, radius)`. Пока C не готов — E использует текущий IslandGen по тому же интерфейсу-обёртке.
3. **АК (B → F):** GLB с узлами `BoltCarrier` (с рукояткой взведения внутри), `Trigger`, `Selector`, `Magazine`, маркеры `muzzle`, `ejection_port`, `ads_anchor`. Пока модели нет — F работает на процедурном «rifle».
4. **Ветер (D):** единственный источник — world.wind_dir/wind_speed/gust + глобальные uniform; остальные только читают.
5. **Материалы (F) → D/C:** `Materials.of(node_or_id)`; поверхности под ногой — `Surfaces.at(pos)`; следы D спрашивают тип поверхности у F, пока API нет — свой текущий способ.

## Правила работы (обязательно)
- Общее рабочее дерево /home/claude/ostrova. **Коммиты только с pathspec** (`git commit -m … -- <свои пути>`), `git pull --rebase --autostash` перед push. Никогда `git add -A`/`commit -a`. Атрибуция — как в напоминании системы.
- Тесты: HANDOFF «Как тестировать быстро» — tests/run_suite.sh, tools/godot_slots.sh (1 рендер + 2 логики), `flock /tmp/claude-0/godot.lock` для импорта. Новый .glb → сначала `--headless --import`. Память 7 ГБ на всех: не держать два тяжёлых Godot сразу.
- **Диск:** свободно ~18 ГБ на всех. Стейджинг моделей с KODAK (device_stage_files, ≤500 МБ за вызов, ≤400 МБ файл) — в /mnt/user-data/uploads; A — не больше 6 ГБ временных файлов одновременно, B — не больше 4 ГБ, остальные — не больше 1 ГБ. Обработал партию → удалил исходники. Большие архивы (>400 МБ, напр. «Разная трава/Textures.zip» 1,5 ГБ, трава PLY 4,9 ГБ) распаковывать на устройстве пользователя в device_bash ($HOME/mnt/Остров — это KODAK/Остров) во временную папку **вне MODELS** (`KODAK/Остров/_tmp_import/`), брать нужное, потом удалить её (удаление — через запрос разрешения, иначе перенести в `_на_удаление`). В MODELS пользователя ничего не менять и не удалять.
- **Размеры в репозитории:** файл < 90 МБ; текстуры ≤ 2K (герои/крупные — 2K, мелочь — 1K), сжатие как в существующих паках; LOD1 обязателен для того, что ставится массово. Исходники (.blend/.rar) в репо не класть.
- Blender в контейнере: /usr/bin/blender (4.0.2). .rar — распаковать на устройстве (на VM пользователя есть unzip; если нет unrar — `pip install --user rarfile` + bsdtar/7z через pip `py7zr` не берёт rar; тогда python unrar-free / или стейджить и распаковывать в контейнере `apt`/pip). FBX/OBJ/blend → GLB через Blender.
- Скриншоты для пользователя — каждый отдельным файлом в /mnt/user-data/outputs/v5_<агент>_*.png.
- В HANDOFF.md — короткая строка о ходе работы раз в ~час и при завершении (только свой абзац, через pathspec).
- Никогда не останавливаться на полпути без записи WIP в HANDOFF (что сделано, что дальше), чтобы при перезапуске продолжить.
